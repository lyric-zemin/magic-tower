# 暗影之塔 · 魔塔远征

一款纯前端的暗黑奇幻文字魔塔游戏。你将穿越三层共 18 间房间，收集 19 类道具与遗物，遭遇 18 种拥有特殊能力的怪物，在商店用金币换取生存空间，最终击败塔顶的暗影幼龙。

项目不需要后端服务，进度自动保存在浏览器本地。

## 特性

- **三层地牢**：暗影地牢、熔岩深渊、星空之塔，包含入口、宝藏、商店、精英、钥匙门和 Boss 房间。
- **19 类道具**：药水、钥匙、武器、护甲、宝石、炸弹、卷轴、戒指与诅咒道具，效果与稀有度各不相同。
- **18 种怪物**：涵盖剧毒、连击、吸血、重甲、狂暴、诅咒、分裂、二阶段等特性，并配有怪物图鉴。
- **逐回合战斗**：交战前显示伤害预览与预计回合数，战斗过程完整写入日志。
- **商店与金币**：击败怪物获得金币，在商店购买有限库存的补给与遗物。
- **键盘与触控**：支持方向键 / WASD 及快捷键，手机端有固定方向控制盘。
- **响应式界面**：桌面三栏、平板两栏、手机单栏布局，适配刘海屏安全区与减少动效偏好。
- **本地存档**：自动保存，带版本号与完整性校验，损坏存档会安全重置。

## 环境要求

- Node.js `20.19+` 或 `22.12+`（与 Vite 8 一致）
- pnpm `9+`，仓库通过 `packageManager` 锁定为 `9.14.2`

推荐使用 Node 自带的 Corepack：

```bash
corepack enable
```

## 快速开始

```bash
pnpm install
pnpm dev
```

启动后打开终端显示的地址，默认是 <http://localhost:5173/magic-tower/>（项目配置了 `base: '/magic-tower'`）。

## 怎么玩

### 操作

| 场景 | 操作 |
| --- | --- |
| 移动 | 点击方向按钮，或按方向键 / `WASD` |
| 切换楼层 | `Q` 上楼，`E` 下楼 |
| 战斗 | 点击「交战」，或按 `F` 与当前房间第一个怪物交战 |
| 拾取 | 点击「拾取」，或按 `R` 拾取第一个物品 |
| 商店 | 在商店房间点击「打开商店」，或按 `B` |
| 图鉴 | 点击顶部「图鉴」，或按 `C` |

房间内有怪物时无法离开；部分房间需要消耗一把钥匙才能进入。击败当前层的守关怪物后，前往楼梯进入下一层。击败第三层 Boss 即通关。

### 道具与商店

- 19 类道具均可在关卡或商店中获得；治疗类道具回血，宝石与武器永久提升属性，钥匙用于开启锁门。
- 爆裂炸弹与回城卷轴为**拾取即生效**：前者立刻对当前房间所有怪物造成 18 点真实伤害（包括发放击杀奖励），后者立刻返回本层入口。
- 生命已满时治疗道具不可拾取/购买；已装备的戒指与靴子不会重复售出；商店不再出售无怪物可炸的炸弹。
- 鹰眼戒指提供暴击，血契戒指提供吸血，可与永久属性叠加；疾风之靴允许逃跑，但每次损失当前生命的 10%，可能导致失败。
- 诅咒药剂会损失 10 点生命，拾取前请先看清效果。
- 商店库存有限。击败怪物会固定获得金币与经验，不会随机掉落道具；合理规划购买顺序是通关关键。

### 怪物与图鉴

18 种怪物全部出现在关卡中，按普通、精英、首领分级。常见特性包括剧毒（持续伤害）、连击（每回合两次攻击）、吸血、重甲（减伤）、狂暴（低血量强化）、诅咒（削弱玩家攻击）、分裂（死亡后产生残影）与二阶段（首领血量下降后攻击大幅提升）。分裂怪的战斗预览已包含残影，不会低估总回合数。

元素属性（火/冰/雷/毒/暗/无）目前仅作为主题与图鉴标签，不参与伤害结算。按 `C` 打开图鉴，查看已遭遇怪物的属性、中文特性名与收集进度；未发现的条目会保持锁定状态。

### 存档

游戏状态保存在浏览器 `localStorage` 中（当前版本键为 `shadow-tower-save-v4`），包含版本号与完整性校验。刷新页面会自动恢复进度；若存档结构不兼容或被破坏，会重置并给出提示。由于关卡内容与玩法规则已调整，旧版本存档会被主动丢弃，避免残留旧数值导致卡关。点击顶部「重开」随时开始新游戏。

锁门只在首次进入时消耗钥匙，已解锁的房间会记录在存档中，离开后再次进入不会重复扣钥匙。

## 技术栈

React 19 · TypeScript 5.9 · Vite 8（beta）· Tailwind CSS 4。除 React 外不引入运行时依赖，图标由内联 SVG 与 CSS 绘制；开发期的平衡自检使用 `tsx` 运行。

## 平衡自检

`pnpm check:balance` 会直接调用生产环境的数据与战斗逻辑，模拟一条完整的标准通关路线，并检查：

- 所有道具与怪物都能在关卡或商店中获得；
- 进入每层 Boss 前的等级、属性与钥匙数量；
- 三个 Boss 均可击败，且战斗不超过 50 回合上限；
- 三扇锁门的钥匙经济足够，重复进入已解锁房间不会再次扣钥匙；
- 炸弹击杀会发放经验、金币与图鉴；连续逃跑会逐步扣血直至失败；
- 回城卷轴立即返回本层入口，满血治疗与重复遗物不会误购。

任一项不满足时脚本会输出失败原因并以非零状态退出，方便在提交数值调整前本地复现。

## 部署

执行 `pnpm build` 后会生成 `dist/`，可部署到任意静态托管服务。

仓库包含 GitHub Actions 工作流，推送到 `main` 分支时会构建并部署到 GitHub Pages。默认 `vite.config.ts` 中的 `base` 为 `/magic-tower/`；如果你的仓库名或部署路径不同，请同步修改 `base` 后再部署，否则静态资源可能无法加载。

## 开发与贡献

欢迎提交 Issue 和 Pull Request。建议流程：

1. Fork 仓库并创建功能分支。
2. 保持数据与逻辑分离：新增内容优先修改 `src/data/`，战斗和结算规则放在 `src/game/`。
3. 提交前运行 `pnpm check:balance`、`pnpm lint` 和 `pnpm build`。
4. 在 PR 中说明改动内容，以及是否影响存档结构或移动端布局。

新增怪物、道具或房间时，请尽量复用现有配置结构与类型，避免硬编码到组件中。
